Common questions

Why does CS2 crash when I play a FACEIT demo?

It’s caused by pet chickens. Since the Rush Hour update in September 2026, players can raise a pet chicken that follows them around in matches. If someone brings one into a FACEIT match, the demo can crash CS2 as soon as you play it.

Every demo starts with a setup section that CS2 reads before the match begins. A pet chicken only appears when the match starts, together with the players, so its setup data comes later, right at the moment CS2 is creating every player and object at once. CS2 doesn’t handle that correctly and crashes. The bug is in CS2 itself. Pet chickens just make it happen much more often.

This tool works around the bug. It moves the chicken’s setup data into the setup section, where demos that play fine keep it, and removes the late copy. Every chicken is still there, and positions, shots, kills and grenades stay exactly the same.

It doesn’t matter what the chicken looks like, and it can happen on any map. Pet chickens hatch from eggs and have to grow up before they can join a match, which is probably why these crashes only started showing up in late October 2026.

It also fixes garbled text that can stop demo analysis tools from reading the file.

Technical details

The crash is an access violation in engine2.dll in GetClassBaseline. The first DEM_Packet carries an svc_UpdateStringTable that adds a new instancebaseline entry (usually CChicken, from a pet chicken that spawns with the players) together with the first non-delta PacketEntities. The tool appends that entry to the signon svc_CreateStringTable and the DEM_StringTables snapshot, then removes the duplicate instancebaseline and AnimAssetData updates from that packet and from the DEM_FullPacket at the same tick. It also repairs invalid UTF-8 in game event strings. Every other message is copied byte for byte.

Why do some FACEIT demos still play fine?

Because nobody in that match brought a pet chicken. The crash is triggered by a pet chicken appearing at the start of the match, so a demo without one loads normally. That’s why the same map can play fine in one match and crash in the next: it depends on the players, not the map.

How do I know if my demo has this problem?

The game closes as soon as you run playdemo, while the demo is still loading. Most of these demos come from FACEIT. If you’re not sure, drop the file in anyway: the fixer checks it first and only changes demos that have the problem.

Do I need to extract the .dem.zst file first?

No. FACEIT demos usually download as .dem.zst, and you can drop that file in as it is (.dem.gz works too). If the demo doesn’t need a repair, you still get the extracted .dem to play.

Are my demo files uploaded?

No. The repair runs in your browser and the file never leaves your computer. The only thing the page sends is a +1 to the shared count of repaired demos, kept on abacus.jasoncameron.dev, without the file name or anything from the file. The source code is on GitHub.

What if the demo still crashes?

If the fixer says no repair is needed, or the repaired demo still crashes, the crash has a cause this tool doesn’t handle. The fixer also tells you when a file is a CS:GO demo, which CS2 can’t play, or when a download was cut off.
